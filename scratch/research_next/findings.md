# S6E9 public candidate refresh — 2026-09-19

No candidate found with primary-source evidence of beating our 0.94656 public best, and none can guarantee first place. This was a bounded search of current Kaggle notebook listings sorted by score and latest run, current dataset listings, and selected downloaded source notebooks. It does not establish that no stronger private solution exists.

## Evidence

- Kaggle CLI `kernels list --competition playground-series-s6e9 --sort-by scoreDescending --page-size 25` returned the already-used 0.94656 band-swap family at the top. [Megayak's source](https://www.kaggle.com/code/megayak/s6e9-0-94656-reading-the-public-split) and [Aman Atar's current notebook](https://www.kaggle.com/code/amanatar/s6e9-samart-sota-meta-blend-lb-0-94656-champion) remain the highest listed entries. This is a notebook listing, not proof that all teams' best predictions are public.
- [Zhenrui Weng's new RealMLP residual notebook](https://www.kaggle.com/code/zhenruiweng/residual-learning-with-realmlp-in-tabular-dataset) claims 0.94572 OOF for its final 10-fold model. Its source supports five-fold tuning with seed 42 and nested target encoding, but final configuration is ten-fold. Downloadable kernel output contains `submission.csv` plus log, no OOF vector. This offers an architectural hypothesis (recipe-margin MLP), not an immediately verifiable improvement or compatible ready-to-blend OOF. Its reported OOF is below our existing memory-residual model. No downloaded code was executed.
- [Najiama's refreshed OOF dataset](https://www.kaggle.com/datasets/najiama/s6e9-oof) was last updated Sep 17. Files include Pure LGBM V1/V3/V5/V6, Sergey LGBM, XGBoost Triple-TE 5-fold/10-fold, and blend predictions. [Current LGBM training source](https://www.kaggle.com/code/najiama/pure-lgbm-model-cv-0-94607-lb-0-94638) claims OOF 0.94607/public 0.94638. [Current blend source](https://www.kaggle.com/code/najiama/oof-power-two-single-models-blend-lb-0-94638) claims OOF 0.94613/public 0.94638 for V3+focal. No evidence of a new model exceeding our frontier was found. Existing project already evaluated this model family, so a date refresh alone is insufficient justification to resubmit.
- [Latest TabPFN notebook](https://www.kaggle.com/code/obiaf88/predicting-electric-vehicle-purchases-tabpfn-3) uses `train_test_split(train_size=10000, stratify=y, random_state=42)` for validation and 150,000 rows for final training. It provides no compatible five-fold OOF evidence.
- [Feature ablation notebook](https://www.kaggle.com/code/rugvedbane/i-tested-15-features-1-did-all-the-work) has seed-42 five-fold code but reports approximately 0.94328 OOF, with a different final 10-fold pipeline at 0.94590 public. Its digit/target-encoding features overlap ideas already tried. [Noise-bar notebook](https://www.kaggle.com/code/amirhosseinkarimiee/the-noise-bar-feature-engineering) also explores digit/frequency/target/window features already represented in the project's pool; no verified stronger candidate identified.

## Decision

Do not spend three submissions on these sources under the user's condition of guaranteed improvement. The strongest useful next experiment is a genuinely new model trained and validated on the exact existing seed-42 five-fold indices, with saved fold provenance, followed by a frozen-weight comparison to the memory-residual baseline. That is research, with uncertain outcome, not evidence of a guaranteed leaderboard win. In particular, ten-fold OOF must not be relabeled as five-fold merely by evaluating its rows in five groups.

Downloaded source snapshots and readable extracts are under `scratch/research_next/`. The only executable run in this research was our own JSON-to-text notebook extractor; downloaded notebooks were not executed. No submissions were made.
